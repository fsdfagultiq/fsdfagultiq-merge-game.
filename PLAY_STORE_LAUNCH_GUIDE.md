**Advertising ID technical note:** apps targeting Android 13+ (API 33+) need `com.google.android.gms.permission.AD_ID` in the merged manifest. The Google Mobile Ads SDK (play-services-ads) adds it automatically through manifest merging. After building, confirm it: in Android Studio open `android/app/src/main/AndroidManifest.xml` → *Merged Manifest* tab, or run `aapt dump permissions app-release.apk`. Don't strip it.

**AdMob ad content safety (recommended):** in AdMob → *Blocking controls → Content* (or app settings), set **Maximum ad content rating = T (Teen)** or **PG**. Do **not** enable "tag for child-directed treatment" (TFCD) or "tag for under age of consent" (TFUA) globally, because the app isn't child-directed. Keep `tagForChildDirectedTreatment` unset or false in code.

## 4. Data safety form

Play Console → App content → **Data safety**.

Source of truth: Google's AdMob disclosure page, **https://developers.google.com/admob/android/privacy/play-data-disclosure**. Google updates it with SDK versions, so **check it against the exact `play-services-ads` / UMP version in your build before you submit.** The answers below match what that page has said for recent SDK versions combined with this app's own behaviour (no backend, no analytics SDK, local-only save data).

### 4.1 Data collection and security

| Question | Answer | Why |
|---|---|---|
| Does your app collect or share any of the required user data types? | **Yes** | The AdMob SDK sends data off the device |
| Is all of the user data collected by your app encrypted in transit? | **Yes** | AdMob/UMP/Play Billing all use HTTPS/TLS |
| Do you provide a way for users to request that their data is deleted? | **Yes** (recommended) | Users can email `[YOUR SUPPORT EMAIL]`, reset or delete their Advertising ID, and uninstall to wipe local data. If you would rather answer No, that is also allowed, because you hold no data server-side. Saying Yes with a working email is more transparent. Add the request method to the privacy policy (it's already there). |
| Independent security review (MASA) | Optional: leave off | |
| Account creation | **My app does not allow users to create an account** (if asked) | |

### 4.2 Data types: declare these

For every type: **Collected = Yes; Shared = Yes** (data goes to Google, a third party, for advertising). **Processed ephemerally = No.** **Required or optional = Required** (users can't use the app without the ad SDK running; consent changes personalization, not whether the SDK collects data. Some developers mark it optional because of UMP. Required is the safer, more conservative answer).

| Category → Type | Collected | Shared | Purposes to tick |
|---|---|---|---|
| **Location → Approximate location** (derived from IP by AdMob) | Yes | Yes | Advertising or marketing; Analytics; Fraud prevention, security, and compliance |
| **App activity → App interactions** (ad views/taps, rewarded completions) | Yes | Yes | Advertising or marketing; Analytics; Fraud prevention, security, and compliance |
| **App info and performance → Crash logs** | Yes | Yes | Analytics; Fraud prevention, security, and compliance |
| **App info and performance → Diagnostics** | Yes | Yes | Analytics; Advertising or marketing; Fraud prevention, security, and compliance |
| **App info and performance → Other app performance data** | Yes, *if listed on Google's AdMob page for your SDK version* | Yes | Analytics; Fraud prevention, security, and compliance |
| **Device or other IDs → Device or other IDs** (Advertising ID, app set ID) | Yes | Yes | Advertising or marketing; Analytics; Fraud prevention, security, and compliance |

> "Shared" judgement call: Play's definitions exempt transfers to a *service provider* processing data on your behalf. Google's AdMob page has historically told developers to declare these types as **shared** when ads are personalized or used for Google's own purposes. Follow whatever the current AdMob disclosure page says. If in doubt, declaring "shared" is the conservative answer.

### 4.3 Data types: do NOT declare

| Type | Reason |
|---|---|
| **Financial info → Purchase history** | Purchases go through **Google Play Billing**. The app receives only a purchase token and product ID, stores the entitlement locally, and sends nothing to a developer server. Play's guidance says data collected by Google Play's own billing flow doesn't need to be declared, and nothing is "collected" by you (collection means transmitted off the device by your app or its SDKs to you or a third party). **If you later add server-side receipt validation or send purchases to an analytics tool, you must declare Purchase history.** Verify in Play Console help ("Data safety: payment info"). |
| Financial info → Payment info / credit card | Never seen by the app |
| Personal info (name, email, user IDs, address, phone…) | None collected. Support emails you receive voluntarily outside the app don't count. |
| Precise location | No location permission |
| Messages, Photos/videos, Audio, Files, Calendar, Contacts | None |
| Health & fitness | None |
| Web browsing | None |
| App activity → In-app search history, Installed apps, Other user-generated content | None |
| Game progress / local save | Stays on device, so it isn't "collected" |

### 4.4 Final check before submit
- Open the preview card in the form. It should read roughly: *"This app may share these data types with third parties: Location, App activity, App info and performance, Device or other IDs"* and *"Data is encrypted in transit"*.
- Make sure the privacy policy URL is live and its contents match these answers.

## 6. Launch checklist, step by step

### 6.0 One-time account setup (allow several days)
- [ ] Create a Google Play Console developer account ($25 one-time). Personal accounts need **identity verification** and **verification on an Android device** through the Play Console app. Organizations need a D-U-N-S number. **Verify the current requirements in Play Console.**
- [ ] Create the app: **Create app** → name *Dim Sum Drop: Night Market* → language English (US) → **Game** → **Free** → accept the declarations.
- [ ] Create an AdMob account at https://admob.google.com and link the payment profile.

### 6.1 AdMob IDs: about 5 minutes
1. AdMob → **Apps → Add app** → Android → "Is the app listed on a supported app store?" → **No** for now (link it to the store after it goes live) → name *Dim Sum Drop: Night Market*. Copy the **App ID** (`ca-app-pub-XXXXXXXXXXXXXXXX~YYYYYYYYYY`).
2. **Ad units → Add ad unit → Rewarded** → name `rewarded_main` → copy its ID (`ca-app-pub-…/…`).
3. **Add ad unit → Interstitial** → name `interstitial_gameover` → copy its ID.
4. Open `www/store-config.js` and paste the IDs into `ADMOB.android` (the app ID, rewarded unit and interstitial unit fields). Then set:
   ```js
   USE_MOCK_ADS: false,
   ```
   Leave the iOS IDs as they are until you ship iOS.
5. Open `android/app/src/main/AndroidManifest.xml` and replace the **test** App ID in:
   ```xml
   <meta-data
       android:name="com.google.android.gms.ads.APPLICATION_ID"
       android:value="ca-app-pub-3940256099942544~3347511713"/>   <!-- TEST: replace -->
   ```
   with your real App ID from step 1. The App ID uses `~`; ad unit IDs use `/`. Mixing them up crashes the app on launch.
6. **Never click your own live ads.** For QA, add your phone as a test device: AdMob → Settings → *Test devices*, or the logcat hint printed by the SDK.

### 6.2 Consent message (UMP), about 5 minutes
1. AdMob → **Privacy & messaging**.
2. **European regulations (GDPR)** → *Create message* → select the app → languages (English + Indonesian, plus any EEA languages you want) → enable "Close (do not consent)" if you want it → **Publish**. Google requires a Google-certified CMP for EEA/UK traffic; UMP is one.
3. **US state regulations** → *Create message* → select the app → **Publish**. This covers CCPA/CPRA and other US state laws and adds the "opt out of sale/share" option.
4. Check that the in-game **Settings → Privacy choices** button opens the UMP privacy options form (`showPrivacyOptionsForm`). Test from an EEA location with a debug geography setting or a VPN.

### 6.3 In-app products, about 5 minutes
Play Console only lets you create products **after you upload a build that includes the Billing library** (see 6.5). Order: upload to the internal track first, then create the products.

Play Console → **Monetize with Play → Products → In-app products → Create product**:

| Product ID (exact) | Name | Price | Type in code | Notes |
|---|---|---|---|---|
| `remove_ads_pack` | Remove Ads | $2.99 | Non-consumable (never consume) | Removes interstitials + 2x coins |
| `starter_gems` | Starter Gems | $1.99 | Consumable (consume after granting) | 500 gems + 3 wildcards |
| `starter_bundle` | Starter Bundle | $0.99 | One-time; don't consume after granting | 500 gems + 3 wildcards + ads-free preview |

- Product IDs **can't be changed or reused** after creation. Type them exactly.
- Set the price in USD and let Play convert it, or set IDR manually (for example Rp 15,000 / 29,000 / 49,000 rounded; verify pricing templates).
- Add an Indonesian name and description for each product.
- **Activate** each product.
- In `www/store-config.js` set `USE_MOCK_IAP: false,` and confirm the `PRODUCTS` IDs match the table above.
- Add your Google account under Play Console → Settings → **License testing** so test purchases aren't charged.

### 6.4 Upload keystore and signing
1. Create the upload key (run this once and **back it up**; if you lose it you'll have to request an upload key reset):
   ```bash
   keytool -genkey -v -keystore upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
   ```
   Store `upload.jks` and both passwords in a password manager. **Never commit it**; add `*.jks` to `.gitignore`.
2. **Codemagic** (workflow `android-release`):
   - Codemagic → Team/App settings → **Code signing identities → Android keystores** → upload `upload.jks`, enter the keystore password, alias `upload`, and key password, and give it a reference name (for example `upload_keystore`).
   - In `codemagic.yaml` under `android-release` → `environment: android_signing: - upload_keystore`. Codemagic then exports **`CM_KEYSTORE_PATH`, `CM_KEYSTORE_PASSWORD`, `CM_KEY_ALIAS`, `CM_KEY_PASSWORD`**, which `android/app/build.gradle`'s `signingConfigs.release` already reads through `System.getenv(...)` (or from an untracked `android/keystore.properties`).
   - Run the workflow. The artifact is `app-release.aab`.
3. **Local build** (same env vars):
   ```bash
   export CM_KEYSTORE_PATH=/absolute/path/upload.jks
   export CM_KEYSTORE_PASSWORD='…'
   export CM_KEY_ALIAS=upload
   export CM_KEY_PASSWORD='…'
   npx cap sync android
   cd android && ./gradlew bundleRelease
   # output: android/app/build/outputs/bundle/release/app-release.aab
   ```
4. Bump `versionCode` (and `versionName`) in `android/app/build.gradle` for every upload. Play rejects a versionCode it has already seen.

### 6.5 Play App Signing and first upload
1. Play Console → **Test and release → Testing → Internal testing → Create new release**.
2. When prompted, choose **Use Google-generated key** (Play App Signing is mandatory for AABs). Google keeps the app signing key; your `upload.jks` is only the upload key.
3. Upload `app-release.aab`, add release notes, **Save → Review → Roll out** to internal testers. Then create the IAP products (6.3).
4. Optional: copy the **app signing key SHA-1/SHA-256** (Setup → App signing) for any Google APIs that need it.

### 6.6 Store listing and graphics
Play Console → **Grow → Store presence → Main store listing**: paste section 1, then add the Indonesian translation (section 2). Upload from `store-assets/`:

| Asset | File | Spec |
|---|---|---|
| App icon | `store-assets/app-icon-512.png` | 512×512 PNG (32-bit, ≤1 MB). Play applies the rounded mask, so don't pre-round it |
| Feature graphic | `store-assets/feature-graphic-1024x500.png` | 1024×500 JPG/24-bit PNG, no alpha (the generated file is fully opaque; regenerate any time with `npm run assets`) |
| Phone screenshots | `store-assets/screenshot-1-gameplay.png`, `screenshot-2-fever.png`, `screenshot-3-stall.png`, `screenshot-4-shop.png` | 1080×1920 (9:16). Minimum 2, maximum 8. Games need at least 4 portrait screenshots at 1080px+ to be eligible for some featuring/recommendation surfaces (verify in Play Console) |

Also fill **Store settings**: category **Puzzle**, tags, contact email `[YOUR SUPPORT EMAIL]`, website (needed for app-ads.txt, see 6.8).

### 6.7 Host the privacy policy on GitHub Pages
1. Create a public repo. For app-ads.txt it's best to use **`<username>.github.io`** (a user site serves files at the domain root).
2. Copy `store-assets/privacy-policy.html` into it as `privacy-policy.html`, then **replace every highlighted placeholder** (`[YOUR NAME / STUDIO]`, `[YOUR SUPPORT EMAIL]`). Search for `class="ph"`.
3. Repo → Settings → **Pages** → Deploy from branch `main` / root → wait about 1 minute.
4. URL: `https://<username>.github.io/privacy-policy.html`. Open it on your phone to confirm it loads, then paste it into **App content → Privacy policy** and the store listing description.

### 6.8 app-ads.txt
1. AdMob → **Apps → View all apps → app-ads.txt** (or Settings) → copy your line:
   ```
   google.com, pub-XXXXXXXXXXXXXXXX, DIRECT, f08c47fec0942fa0
   ```
2. Put it in a file named `app-ads.txt` at the **root** of the developer website listed on Play, for example `https://<username>.github.io/app-ads.txt`. A project-page path like `/repo/app-ads.txt` doesn't count.
3. Enter that website in Play Console → Store settings → **Website** exactly (same domain).
4. After the app is live, link it in AdMob (Apps → App settings → *Add app store details*). AdMob crawls app-ads.txt within about 24 hours. Until it's verified, ad serving may be limited.

### 6.9 Closed test: 12 testers for 14 days (new personal accounts)
Personal developer accounts created after 13 Nov 2023 must run a **closed test with at least 12 testers who stay opted in for at least 14 consecutive days** before they can apply for production access. (Google lowered this from 20 testers in late 2024. **Verify the current numbers in Play Console → Dashboard.**)

1. Recruit 15 to 20 people (have extras in case some drop out). They need Android devices and Google accounts.
2. **Test and release → Testing → Closed testing → Create track** (or use "Alpha") → **Testers** tab → choose **Email list** (paste their Gmail addresses) or a **Google Group** (easier: testers join the group themselves).
3. Create a release on the closed track with your signed `.aab` → **Review → Roll out**. Complete the App content items first, because the closed track goes through review too.
4. Copy the **opt-in link** (Testers tab → "Join on Android/web") and send it to testers. Each tester must (a) open the link and tap **Become a tester**, then (b) install the app from the Play Store link.
5. Keep them **opted in and installed for 14 consecutive days**. The counter only includes testers who are opted in. Ask them to actually play (Google asks about engagement), and collect feedback in a Google Form or chat group.
6. Push 1 or 2 updates during the test (fixes or polish). This shows active development in the application.
7. After day 14, open the Dashboard → **Apply for production** → answer the questions about your test (how you recruited testers, feedback received, changes made, why it's ready). Google's review typically takes up to about 7 days.
8. When approved: **Production → Create new release** → promote the tested build → choose countries (all, or start with Indonesia plus a few markets) → consider a **staged rollout** (20% → 50% → 100%).

### 6.10 Pre-launch sanity checks
- [ ] `USE_MOCK_ADS: false`, `USE_MOCK_IAP: false`, real AdMob IDs in both `store-config.js` and the manifest.
- [ ] Interstitials appear only from run 2 onward, every 2nd game over, and never after Remove Ads.
- [ ] Rewarded ads grant their reward only on the completion callback.
- [ ] The consent form appears in EEA testing, and **Settings → Privacy choices** reopens it.
- [ ] Test purchase of each product with a license tester. `remove_ads_pack` restores after reinstall (via `queryPurchases`). `starter_gems` can be bought again.
- [ ] Airplane mode: the game works and the ad buttons fail gracefully.
- [ ] Pre-launch report (Play Console → Testing → Pre-launch report) has no crashes or accessibility blockers.

## 7. Promotion: launch week

- **Short vertical clips (TikTok, Instagram Reels, YouTube Shorts):** 7 to 15 second screen recordings of chain merges ending in a Giant Hotpot, near-misses saved by the 3-second grace timer, and Wok Fever x5 moments. Hook in the first second ("POV: one more merge…"). Use original or royalty-free audio; the game's own lo-fi track works. Post 1 to 2 a day during launch week.
- **Indonesian communities:** food and kuliner communities, mobile gaming groups on Facebook, TikTok creators who cover game santai or game offline, and Kaskus/Reddit r/indonesia, following each community's self-promo rules. Pair the night market (pasar malam) theme with real jajanan culture content. Never use fake reviews or incentivized ratings, which violate Play policy.
